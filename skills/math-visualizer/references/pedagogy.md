# 教学拆解与讲解写作

## 从题目到知识要点

不要罗列整章知识。先写求解链：已知 → 哪个关系可用 → 必要构造/变形 → 中间结论 → 目标。
给每个知识点指定角色：

| 角色 | 判断 | 页面处理 |
| --- | --- | --- |
| 前置知识 | 学生需要先会，否则无法跟上 | 必要时一句回顾，避免展开整章 |
| 关键关系 | 不理解就只能背答案/口诀 | 主要解释及图形资源投在这里 |
| 运算步骤 | 承接关键关系的计算 | 简短公式，长计算可展开 |
| 迁移检查 | 换一个条件仍能判断 | 一个预测/口头追问，不要求测评系统 |

先完整解题再缩短文案。简洁不能删掉适用条件、端点或证明。不要用“显然”“由图知”“套公式”“现成规矩”遮住关键推理。

## 点明关键的一句话

格式可参考“因为【关系/不变量】，所以把【原问题】转成【更容易判断的对象】”。一句只讲一个关键联系，不强制固定字数。

- 平移：要保持原来的函数值，新横坐标必须补回括号里减去的量。
- 分段单调：先分别判断函数在各区间上的单调性，再比较分段点两侧的函数值。以分段点为 0 为例，还需证明：任取 x₁<0≤x₂，都有 f(x₁)<f(x₂)。
- 空间线面角：先找向量在平面内的投影，再比较垂直分量与原长度。
- 概率条件化：条件发生后，分母要换成条件内的样本空间。
- 离散分组：等差数列的等差关系可以转成下标间距关系。

避免“本题考查函数、导数、数形结合”等标签替代解释。

## 讲解单位

每一步围绕一个学习动作组织：提出要判断的问题 → 观察/操作 → 解释原因 → 必要结论。不是每一步都需要四块 UI；一句提问、一幅图、一行公式往往足够。
步骤数量由推理决定。不要把已有五步二次函数模板硬套到概率、空间题。

首次学习时：待求坐标/选项/数值逐步出现。可先画满足已知条件的图形引导猜测，但不能将待证结论作为构图输入，再用它证明自己。已知条件可以直接标出。

交互先限制关键变量，建立因果关系后再开放多参数。每个控件要有观察任务。例如“增大 a，观察左侧斜率何时变负”，而不是只写“拖动试试”。

## 原题、动点和变式

原题本来包含的参数讨论、动点运动不是变式。应在原题合法范围内操作。改变原题的固定常数才是变式，需明确标识新题条件。镜头旋转只改变观察方式，不改变题目。
固定正文若仍用于原题，就不要与新图并排形成假对应。可选择：同步正文、暂停原题步骤并进入独立探索、或者清楚标注原题/变式两列。

## 反例与诊断

在有必要的地方选择能推翻常见错误的例子：
- 分段函数：每段各自递增，但存在 x₁<0≤x₂ 而 f(x₁)>f(x₂)，用这个反例纠正“分段递增就全局递增”。
- 参数图：用边界等号判断相切是否符合“两交点”，不能只拖几个值。
- 概率：末次停止可以由“命中”或“达到上限”引起，不能漏末项质量。
- 空间图：旋转镜头使屏幕角变化，而真实垂直关系保持，区分投影与实体。

收尾让学生解释原因而不是复述坐标。已会简单运算的高中生做一行复数计算或中位数，不默认加复杂交互。

## 中文讲解与图文衔接：避免把提纲当讲解

老师是操作者，学生是课堂讲解的读者。页面可以简短，但不能让学生靠猜补出对象和因果关系。以学生已有知识为尺度，不强行把所有数学术语改成幼儿化口语。

### 中文表达的硬性要求

- 语义必须连贯。前一句建立的对象与问题，后一句要接得上；转换讨论对象时明确说明，不能突然换成新的线、点、数值或结论。
- 不可省略理解所必需的信息。谁与谁有什么关系、条件是什么、为什么能推出下一步，都必须交代清楚。使用“这”“它”“另一条”等指代前，要有唯一明确的对象。
- 必须符合中国人的用语习惯。按自然的中文语序写完整句子，使用课堂中常见、准确的数学表达；避免翻译腔、名词堆叠以及“分别贡献”“建立因果”等内部工作用语直接进入学生讲稿。
- 简明通过分句、分步和图文同步实现，不通过删掉主语、条件或理由实现。允许省略不影响理解的重复信息，但不能以“老师会补充”为理由留下必要解释的空缺。
- 交付前按屏幕顺序逐句朗读，再连读前后两步。检查是否顺口、指代是否明确、推理是否完整；数学术语正确不代表整句话自然，语法成立也不代表学生能理解。

### 编写时执行

1. **先交代目标。** 初始画面保留原题的核心条件及所求；长题干、选项、备注可以折叠。局部提问不能替代最终任务，已知条件不属于答案泄露。
2. **先指对象，再说关系。** “这个点”“近处”“另一条线”必须有已建立的指代。图上先标出对象或同步高亮，再说明它与谁有什么关系。短句保留必要主语；“两条轨迹，分别贡献”之类内部笔记不能直接进入课堂页面。
3. **关键转化说明为什么。** 从原题转为新对象时，解释新对象怎样满足原条件，以及为什么没有遗漏或多算。引入辅助线后不能立刻开始数交点；先讲清这些交点为什么就是原题要找的点。
4. **一段话只跨一个理解环节。** 难点处按“指明对象→展示关系→解释含义→得出局部结论”分次呈现，不把整个链条压成一句口号。步骤数随理解难点变化，不强制五步；操作提示不能挤掉数学理由。
5. **文字所说的关系要在图上可辨。** 距离要看清从哪里到哪里，必要时画垂足和直角标记；同值但不同对象的量分别命名。重叠线段可分次高亮。不能只用一句“注意不是同一个距离”弥补图示缺失。
6. **从观察接回一般推理。** 代表值用于比较，不代表整个区间。写出图形关系对应的不等式、边界及分类依据，再得出范围。当前问题与参数一致；固定问“r=3时”却允许图停在r=2时，应改成一般提问，或明确提供跳到3的操作及当前状态说明。

### 用户仍然说“读不懂”时

先定位缺口：不知道在指谁、术语未解释、句子语法不顺、一次关系太多、关键推理跳步，还是图形无法支持文字。不要把“分别计数”换成“把点数相加”就认为解决；修改后检查学生是否能指出对象，并解释这一步为什么服务于原题。需要补图层或拆步骤时，不能只润色文字。

以下为本项目圆与直线样稿暴露的反例，不是所有题的固定讲稿：

| 不合格表达 | 问题 | 改写与画面配合 |
| --- | --- | --- |
| “点既要在圆上，又要到原直线的距离为1” | 语法拗口，点未建立，距离含义未呈现 | 先标P：“在圆上选一个点P。从P向题目给出的直线作垂线。如果这段垂线长为1，P就符合题目的距离要求。”同步出现垂线、垂足和长度；此前保留“恰有两个点，求半径范围”的目标。 |
| “分别数出圆与两条辅助直线的交点，再把点数相加” | 语句本身可成立，但若辅助线的来源未讲清，仍然读不懂 | 先解释到原直线距离为1的所有点组成哪两条线。再在r=3的图上逐条高亮：“圆与第一条线有两个交点。圆与第二条线相切，只有一个公共点。因此共有三个点符合要求，这个半径不符合题意。” |
| “较远轨迹还未相交” | “轨迹”指代负担重，“未相交”可能被理解为包含相切 | 命名直线m₂，明确“圆与m₂没有公共点，需要r<3”；与另一条件r>1合并，说明为何取开区间。 |

“碰到”可用于引导观察，但不能替代相交、相切、公共点的精确区分。已学过的术语可直接使用；新构造的对象仍须建立指代。目标是自然、明确、数学准确，而不是一律口语化。

以下为本项目分段函数样稿（2024 年单调性题）暴露的反例，与上表圆题反例同理，均不是固定讲稿：

| 不合格表达 | 问题 | 改写与画面配合 |
| --- | --- | --- |
| “若 −a＞1，就能在 0 左侧找到函数值大于 f(0) 的点” | “就能找到”是断言，没有交代为什么存在这样的点 | 先讲“左段递增，且 x 趋近 0（仍小于 0）时函数值无限接近 −a”，再推出“只要 −a＞1，就能取到足够接近 0 的负数 x₁ 使 f(x₁)＞1=f(0)”；图上画高度为 1 的水平参考线，并用同值点连线让“左段越过参考线”直接可辨 |
| “任取 x₁＜0≤x₂，还有：f(x₁)＜−a≤1≤f(x₂)” | 两个不等式没有来源，“还有”掩盖了推理；−a≤1 正是条件 a≥−1 的使用处，也没有点名 | 先立两界——左段上确界 −a（碰不到、能任意接近），右段最小值 f(0)=1——再写“于是 f(x₁)＜−a 且 f(x₂)≥1”，最后比较两界得 a≥−1 |
| 把“比较分段点两侧的函数值”当成所有分段函数的通用口诀 | 本题两个界限恰好都出现在分段点附近，是题目结构使然，不是一般规律 | 写明最难满足的组合是“左段函数值尽量高、右段尽量低”，本题两界分别是趋近 0 的 −a 与 f(0)=1；并注明换一道题要按题目重新找这两个界限，不能照搬 |

### 从讲稿到交付页的核对

修改前先确定用户打开的 HTML 来自哪个配置、讲稿或生成脚本；修改生成源后重建，并在实际 HTML 中逐步核对。项目中同题存在多条生成路径时，逐一列出并同步讲解，不把另一条路径的修改当成本页已修复。历史测试证据不覆盖。

步骤标题写清正在判断的数学问题。短标签只用于导航，不能替代正文：例如标签可写“两侧比较”，标题应写“负数对应的函数值能否超过 f(0)？”。禁止用“分开看，再检查接缝”代替这两层信息。

先写一份不依赖作者口头补充的完整讲解，再分配到各步骤。复核者逐步指出：讨论的对象、使用的已知条件、这一步的理由、如何接到下一步。任一项需要猜测，就回到讲稿补足；不要只换近义词。全文过长时按推理环节拆步，不删必要理由来挤进一屏。
