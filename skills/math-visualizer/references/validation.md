# 课件验收

## 四条检查线

| 检查 | 最低证据 | 不足时 |
| --- | --- | --- |
| 数学 | 题意对照、解答依据、精确结果；必要时独立算法核验 | 修正或标 blocked，不改成静态规避 |
| 教学 | 关键句是否解释原因、交互是否有观察目标、答案揭示顺序 | 删除无效控件，改讲解与图层 |
| 状态 | 初始/前进/回退/重置/变式/边界的图文一致 | 修模型与派生关系，再跑受影响状态 |
| 视觉 | 实际截图、关键标签、同屏、窄屏、控制可达 | 修版式；缺工具明确未实测 |

正式 HTML 导出前另有**前置独立教学审校**：讲稿与图文方案的独立 LLM 审校（输入、输出、停止规则与门禁见 [前置独立教学审校](teaching-review.md)）。它检查文字与方案，浏览器验收检查实际呈现，两者不能互相替代；审校通过不证明真实学生理解。

## 固定的验收问题与阻止标准

逐任务回答以下五问，标准不随单次结果更改：

1. 必要对象和关系是否可从当前学生可见内容辨认？不能靠作者补充解释。
2. 文字指向的对象是否唯一明确？无图任务（decision=none）不强制图上身份检查，只核验解答与"不画"的理由。
3. 参数变化、边界和退化时，对象身份、结论、数值是否一致？
4. 需要比较的内容是否能在合理阅读操作中共同查看？同时观察才要求并置；顺序阅读允许滚动，有滚动不自动失败。
5. 是否保留必要理由、条件与答案揭示顺序？

**阻止项**：数学错误、关键理由缺失、必要对象不可辨认、图文矛盾、内容裁切或操作不可用。**不自动判失败**：可恢复的普通刻度省略、可正常阅读的滚动、不同但合理的表示、润色偏好——它们是建议或允许取舍。

**对象身份的呈现方式不限一种**：图中标签、图例、方程标注、线型/颜色配文字说明均可让学生辨认对象；选择适合本题的，但不允许"正文引用的对象在画面上无法辨认"。代码里写了 `label` 调用不算可见证据，SVG 字符串里存在文本也不等于屏幕上可读——身份核验以实际渲染结果（DOM/SVG 提取 + 截图）为准。绘图工具的标签证据（`labelEvidence`，见 [工具 API](toolkit-api.md)）给出每次放置或省略的事实：essential 标签被省略是必须核对的信号（已有等价图例等身份方式时可通过，唯一身份丢失必须阻止），普通 decorative 刻度省略不算缺口。

## 生成前先检查解释方案

按 [交互解释工作流程](explanation-workflow.md) 检查：学生的问题是否顺次衔接；最难的关系是否有对应的可见表示；操作是否能帮助检验具体误解；原题目标是否始终清楚；已有模块是否同时覆盖计算和解释。关键关系缺失就修方案或补呈现，不能先把整页美化后以工程通过代替讲清楚。

## 必测但按题选择的状态

- 初始状态不能泄露尚待推导的坐标/结论（包括图例、caption、隐藏区默认展开、aria 文本）。已知题干不算泄露。
- 前进和回退后，同一步回到相同教学信息；观察参数是否保留应符合任务，不暗改原题。
- 参数最小/最大、临界值及两侧；无交点、相切、交点重合、超出视窗；无定义值/不连续点不能连线。
- 原题 ↔ 变式，公式和正文同步；恢复参数不丢失讲解步骤；键盘重复操作不丢焦点。
- 空间模型至少两个视角；旋转不改变距离/角度计算；退化情形禁止或解释。
- 标签不重叠仍可能误导：刻度和原点不能被避让到别的位置；普通标签移远时要引导线。检查数学对象在图卡中的实际大小，不以容器够大代替图够清楚。普通数值刻度被防碰撞省略时可恢复（移动参数或视窗即再现），不自动失败；正文或关键关系引用的对象标识被省略则按上一节标准判定。
- 离散/概率核验对象计数、分母、总概率与期望。
- 窄屏单独检查图卡空白、长参数标签换行、来源链接溢出；桌面最小高度不能直接套到手机。整页不溢出还不够，应截图确认图形和文字可读。

## 证据分工与覆盖范围

- **机器检查（DOM/SVG 提取）**：定位缺失、裁切、对象显隐与状态一致性错误；标签是否实际渲染以渲染产物中的标签证据为准，不以源码中存在调用为准。
- **真实截图**：检查可读性与图文关系（遮挡、缩放后字号、颜色区分）。两者分工不互替。
- **浏览器按实际表示选择测试**：有控件才测控件，有图才测图；decision=none 只核验解答和"不画"的理由。
- **默认视口**：1366×768、1440×900、390×844。关键状态测图文关系，普通状态做导航/错误/溢出检查，不盲目穷举所有参数×步骤×视口的笛卡尔积。移动端不要求投屏式同屏布局。
- 自定义 renderer 或低层组合路径（不经过配置构建器的页面）承担同样的审校与证据责任：按 [前置独立教学审校](teaching-review.md) 的标准准备实际渲染内容的审校输入并留存记录，未接入自动门禁不得宣称已被脚本覆盖。

## 教学可理解性检查

检查实际页面当前状态，而不只审查讲稿文件。先把实际页面按步骤导出为审查稿（标题、正文、公式、图中标签、提问与代表参数下的动态文字），再只依据学生可见内容逐步回答四问：当前要解决什么问题？新对象是什么、为什么引入？本步结论的依据在哪里？为什么下一步要这样做？每个回答指出页面中的依据；需要审阅者自行补足的关键条件或理由记为解释缺口，文字提到但图上无法辨认的关系记为图文缺口，并区分句子不自然、前提缺失、推理跳步、图形不足、布局遮挡，返回对应环节修复。正文引用的对象标签应核验确实渲染（防碰撞机制可能省略标签；可在 SVG 文本层程序核验），不能只看代码里写了 label。

每个关键转化至少回答：

- 学生能否说出原题最终要求什么，而不是只知道当前要拖什么？
- 句中的点、线、距离、代词分别指向图上哪个对象？新引入的对象有没有说明来源？
- 为什么这一步等价于原条件，或为什么它能推进求解？页面有没有省略必须由教师临时补上的推理？
- 图中能否直接辨认文字描述的关系？重叠距离、同值异义、弱化或隐藏原对象有没有造成误导？
- 更改参数后，标题、问题、解释、公式是否仍与画面对应？
- 学生能否解释区间与端点的理由，而不只是复述几个按钮对应的点数？

失败记录使用“原句/画面状态→预期理解→缺失关系→文字或图层修改→复查”的格式。用户明确反馈读不懂时，不能仅以教师或模型审查通过覆盖该反馈。

数学、交互、教学审查、真实学生理解、用户视觉认可分别报告。专家审查可以发现障碍，不能据此宣称学生已经看懂；没有学生测试就注明。可让独立审查者指出跳步与不自然中文，但不要求每道题强制多代理。

## 报告用语

通过：写明实际范围与证据。未测：列出缺失检查。失败：记录输入、现象、修订、复测结果。
不得用前端无异常代替数学正确；不得用有限点一致代替恒等证明；不得把少量真题抽样称为“近五年全卷通过”。
