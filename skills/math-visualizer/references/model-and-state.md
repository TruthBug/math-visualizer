# 数学模型与教学状态

最小记录可用 Markdown；模型复杂再用 JSON。重点是可追溯，不是字段数量。

```text
source: 原文、来源路径/URL、页码、题号、目标小问、图形核对结果
objects: 对象、变量、单位、定义域
givens: 题目明确条件
constructions: 为推导引入的对象及定义
goals: 待求/待证；不得被构图当作已知
derivation: 每条结论的依据，分情况与边界
teaching: 前置知识、具体误解、学习问题顺序、关键句、预测问题、迁移检查
storyboard: 依照交互解释工作流程，记录关键环节的图文对应、反馈、依据和承接
essentialInfo: 只对关键理解环节记录四项——学习目标（本步结束要解释哪个关系）、必要信息（为解释它不能缺的对象/条件/数值）、呈现方式（学生从图中标签、图例、方程、表格、文字或操作中如何辨认）、检查状态（哪些临界/退化/对照状态最容易使对应失效）；用短段落即可，不要求所有小步骤填表。再补一句布局选择：哪些信息必须并置、哪些允许按顺序阅读
capabilityGaps: 分开记录数学计算与解释呈现的覆盖情况、缺口及扩展方式
intent: concept/worked-example/transfer、学习目标、结论范围；未指定时原题讲解
decision: interactive/static/none/blocked + 理由
representation: 工具、图形中的量与数学量如何对应
state: 原题状态、步骤、观察参数、变式参数
steps: 当前目标、可见图层、可见结论、操作范围、同步说明
verification: 精确推导、独立数值/枚举、状态边界、视觉检查
```

讲解草稿和最难环节的试作要求见 [交互解释工作流程](explanation-workflow.md)。上述新增记录属于作者方案，不是课件 JSON 配置字段，不能直接交给构建器。

## 实现约定

先实现纯函数 `derive(state)` 返回当前对象/数值/解释，再实现 `render(state)`。输入改变后统一更新，避免正文、SVG、图例各存一套参数。
控件节点保持稳定，不在每次滑动时替换获得焦点的元素。范围输入提供 label、键盘支持、步长和当前值。若提供图内拖动，处理 pointercancel、边界和焦点。

参数范围由数学条件决定，显示视窗由教学目的决定，两者不能混为一谈。显示范围不是函数定义域。有限的滑块区间必须标明“演示范围”，对无界数学范围仍需证明。

每个断点单独绘制曲线段，空心/实心点体现开闭。三维选择非退化代表构型，文字写明代表性；证明仍覆盖全部合法构型。

## 精确与近似

整数、分数、根式等用精确表达；显示用小数时注明近似。不将一般式系数舍入后仍写为顶点式的精确等价式。
浮点内部计算可以有容差，但不要据容差更改数学边界。相切与相交、多重根与两个不同根分别处理。

## 样例：首次认识平移

1. 原题：保留原式；可以观察图，不显示待求顶点坐标与平移答案。
2. 配方：只突出补加与补减的项，公式组合法正确；图形不必动画。
3. 顶点/对称：平方项最小、等距横坐标的平方值相同，逐一显示结论。
4. 平移：旧点 `(u,u²)` 对应新点 `(u+h,u²+k)`，先水平后竖直。说明这是整图同一位移。
5. 变式：明确修改条件，同步图文；重置参数保持当前步骤。

这是一种可用顺序，不是其他题型的统一模板。
