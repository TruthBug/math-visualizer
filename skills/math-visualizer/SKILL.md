# 数学单题讲解

## 老师要什么

使用者是备课的数学老师，课件在课堂上由老师操作、投影给学生看。老师拿到的应该是一份能直接上课的东西：

1. **课件**：单文件离线 HTML。题目常驻、图形够大、一步一个问题，老师用翻页笔或方向键推进；可全屏、可调字号、可打印学案。
2. **备课卡**：本题定位与考点、题眼、启发提问链（附预期回答）、预设错误与应对、方法提炼、变式练习、板书要点。页面上默认收起，可单独打印。
3. **说明**：正确解答、为什么这样讲、已测范围。不适合画图的题，给简短解答和不画的理由。

默认简体中文、原题讲解。只说“讲这道题”时不逐次追问教学目的；一次处理一个教学任务，整卷只在用户要求批量或测试时逐题处理。

## 从这里开始：先拆题，再按需读取

新题先读本文件和原题，随即解题。下列资料在需要时读取对应部分，不是启动时的必读队列；已读且未变化的沿用。

| 当前要解决的问题 | 此时读取 |

| 用户要概念课或迁移练习，或教学目的不明确 | [教学意图](references/teaching-intent.md) |

`scripts/`、`assets/` 都相对当前 Skill 根目录；不要假定安装目录名前有 `skills/` 或原作者的仓库。用户讲稿与输出放在用户工作目录，用带引号的路径传给脚本。Python 工具可经 `node scripts/run_python.cjs <脚本> [参数]` 调用。只有 API 说明不够、实际报错或决定改组件时，才读播放器、构建器和审校器源码。安装副本差异检查只在同步、升级或有版本不一致证据时进行，正常备课不先巡检各安装目录。Python 解释器由 `run_python.cjs` 自动查找，不写死个人路径，不把虚拟环境一起分发。

## 流程

1. **核清题意，先解题。** 保留原题、来源和本课要讲的小问；PDF 或图片中的公式、条件、图形对照原页。区分已知、构造、待证和推出，不把图上看起来成立的关系当条件。缺失条件妨碍求解时标 `blocked`，说明缺什么，不自造替代题。

2. **针对疑点核验。** 先指出要核对的公式、边界、计数或极值，再选能查出这类错误的方法：代回、独立推导、符号运算、有限枚举或数值交叉检查。有限采样不能证明一般结论；脚本报错先区分是推导、实现还是断言的问题，不为通过删掉有效检查。数学关系没理清之前，不开始查实现栈。

3. **说题式拆解。** 按[说题式拆解](references/lesson-design.md)回答六问：题目说了什么、考什么、题眼在哪、学生怎么想到、会错在哪、带走什么。再把它排成课堂步骤：审题 → 转化 → 落实 → 回顾，每步一个思维动作、一个页面提问。变式答案和原题一样要核验。

4. **决定画不画。** 图只服务两件事：让题眼那一步的关系看得见，让预设错误在某个状态下暴露出来。据此选 `none`、`static` 或 `interactive`，写一句理由；确有取舍时比较两种表示。`none` 给解答和不画的理由，仍做内容核验与审校，跳过工具选型、HTML 和浏览器环节。不能因工具不足把必要的交互降为静态。

5. **选实现路径，写讲稿并试作。** 按“配置可覆盖 → 已有工具可组合 → 真实能力缺口才扩展”判断；没有同名题型模块不等于必须新增模块。先写一份连续读得懂的讲稿，再分到各步，分配图、文、操作各自的任务；配置路径把六问结果写进 `prep`。只试作最难的关系和容易失效的边界，能表达后再补齐。预览用 `--preview`，带明显标记，不得写进正式交付目录。

6. **冻结输入，独立教学审校。** 用实际讲稿源、渲染文字、对象身份、代表状态和备课卡执行[审校协议](references/teaching-review.md)。只修阻止项及必要关联内容，非阻止建议默认登记；周期、预算和停止条件只在协议里维护。缺记录、未完成、有阻止项或已过期时，构建器拒绝正式导出。低层组合页同样要独立审校并留存同源证据，不能因未接入脚本门禁而跳过。

7. **正式生成并验收。** 审校通过后生成，按[验收](references/validation.md)分别检查数学、教学、视觉、交互：普通状态用程序遍历，关键图文用截图核对并放大焦点区域；投影常用的 1366×768、1440×900 和手机 390×844 都看。只复测改动影响的状态。缺浏览器能力如实写“未实测”。

8. **交付并停止。** 交付课件、备课卡要点、已测范围和限制；不适合画的题交付简短解答和理由。新任务只要求当前产物可用，不自动扩展成公共模块或多副本维护；确实改了共享 Skill，验证通过后集中同步。未经要求不发布到外网。

## 不可遗漏的约束

- **揭示一致：** 图、公式、图例、说明、无障碍文本都服从当前步骤；不能正文还没推出答案，顶点标签或图注已经写出来。复习场景可以先给结论，但要有明确教学目的。备课卡只给老师看，不算向学生揭示。
- **同一状态：** 图形、数值和解释从同一模型派生。原题固定条件不做普通滑块；原题允许的动点与修改题目条件（变式）分开呈现。恢复原题参数不强迫退回第一步；重新讲解用另一个按钮。
- **数学诚实：** 精确值与近似值分开，约数用 `≈` 或“约”；有限采样、实例展示、符号恒等验证、一般证明各有适用范围。条件不足和“不值得画”不是同一个结论。
- **表示诚实：** 平移展示对应点和位移，导数展示切线与增减，空间角在合适的截面里看；屏幕上的长度和角度不等于三维真实值。拖动点必须保持已知约束，不能用结论约束构图。
- **课堂可用：** 首步保留核心条件与最终所求，多问的题写明本课处理哪几问，不能只藏在折叠的备课提示里。图、当前公式、当前解释和推进按钮尽量同屏；每步图上只突出一个焦点对象或关系，图内文字只标身份（画规见[教学设计](references/pedagogy.md)）。颜色同时配文字或线型。老师控制节奏，不自动循环播放。
- **思路可迁移：** 页面不只展示做法，还要让学生看到“为什么想到这样做”；回顾步骤写出通法。预设错误必须有对应的暴露状态，不能只在备课卡里写一句提醒。
- **中文表达：** 按[数学教材语言与表述规范](references/math-language.md)检查术语、句法、对象指代、量词逻辑、符号和推理承接。能明确定位的病句或用语错误必须修，不能因答案正确降为文风偏好；教材版本差异要有依据。内容多时分句或分步，不删必要的条件和理由。
- **讲解可理解：** 面向老师操作，不等于页面可以只写解题提纲。按学生前置知识写完整关系，先明确对象再解释操作和理由；关键转化不能靠老师自行补全。用户说“读不懂”时，按[教学设计](references/pedagogy.md)检查指代、术语和推理缺口，不只换近义词。数学和交互通过不等于教学通过。
- **审校前置：** 正式 HTML 只能来自当前版本的已审校讲稿；不合格、未完成或过期的审校必须阻止导出。不把非阻止项当作继续循环的理由，不为达标删除失败断言，不以新增脚本、文档或测试通过宣称教学问题已解决。

## 页面与工具边界

- **课件外壳由 Skill 提供，不逐题重写。** 配置路径的页面骨架、`classroom.css` 和 `player.js` 已包含：题目条、分步导航（方向键、翻页笔 PageUp/PageDown）、全屏（F 键）、字号调节、备课卡抽屉、学案与备课卡打印。新题只写模型参数、讲稿和 `prep`。
- **路线已收敛（2026-09-19）：** 配置路径（build_lesson + modules + player）是唯一演进路径，新能力只进 modules.js 契约；lesson.js 脚本壳已冻结，只作低层组合参考。配套案例逐步迁移为配置构建，同一题只保留配置一个真源；迁移状态见[配套案例](references/examples.md)。
- **案例快照只同步、不手改：** `assets/examples/` 是宿主仓库同步脚本写入的分发快照。要改案例，先改真源、完成当前输入的独立审校，再正式构建、浏览器验收，最后同步并核对分发文件。内嵌资产滞后时 `check_package.py` 只警告，不代表教学合格。
- **同题多版本：** 同一题有多个版本（不同教学目的或生成路径）时，先列清单（目标 HTML、讲稿源、构建方式、分发位置）；目标相同的版本共用讲稿数据，目标不同的写明区别。改了一个版本，要在实际 HTML 里核对本路径确实已改。
- 主要使用者是老师，输出面向备课与课堂演示，不默认扩展学生端、家长端或账户平台。
- 工具是轻量 SVG、坐标与向量辅助，不是通用解题器；数学由调用 Skill 的 Agent 推导并核验。能力清单区分已实现模块、低层工具和尚未接入的库；不能因为文档提到 Three.js 就宣称可以直接调用。
- 三维示例使用可旋转正交投影；复杂遮挡或曲面按[工具选择](references/tools-and-presentation.md)选专用库。
- `scripts/check_package.py` 检查打包结构与引用；`scripts/bundle.py` 只嵌入明确标记的本地资源，不执行题目文字。
- 高考测试只证明所列题目的已覆盖路径；不能以“十题通过”声称所有年份、整卷或所有几何构型都已通过。
