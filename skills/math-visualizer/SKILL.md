# 数学单题可视化

目标：围绕教师的教学任务生成课件，题目可以是输入和素材。先明确要建立概念、讲解原题还是检查迁移，再找学生需要理解的关系、决定是否画图。默认简体中文、老师操作、学生观看；只要求“讲这道题”时默认原题讲解，不逐次追问。一次处理一个教学任务，整卷只在用户要求测试/批量时逐题处理。

## 从这里开始：先判断，再按需读取

新题先读本文件和原题，随即确认条件并开始推导。后续资料在下列条件满足时读取相关小节；链接不是启动时的必读队列，不递归展开所有引用，已读且未变化的资料沿用。

| 当前需要解决的问题 | 此时读取 |
| --- | --- |
| 用户要求概念课/迁移练习，或教学目的不明确 | [教学意图](references/teaching-intent.md)；普通“讲这道题”直接默认原题讲解 |
| 已有解答，需要组织难点、检查理解或图文承接 | [教学设计](references/pedagogy.md)、[解释工作流](references/explanation-workflow.md)的相关部分 |
| 已决定需要图形，准备选择实现路径 | 运行 `node scripts/list_capabilities.cjs`，按[复用与扩展](references/reuse-and-extension.md)选路径；选中后才读匹配配置或[绘图 API](references/toolkit-api.md) |
| 需要多步骤/动态状态或记录图文分工 | [模型与状态](references/model-and-state.md)；复杂表示或公式排版选择再查[工具选择](references/tools-and-presentation.md) |
| 准备试作与验收；源稿定稿准备审校 | 分别读[验收](references/validation.md)、[审校协议](references/teaching-review.md)，本任务后续复用 |

使用当前加载的 Skill 路径。安装副本差异检查仅在同步、升级或有版本不一致证据时进行；正常解题不先巡检各安装目录。仅在 API 说明不足、实际报错或已决定修改组件时，读取对应源码/测试，不预读播放器、构建器和审校器内部实现。

## 执行流程与判断节点

1. **确认输入并先解题。** 保留原题、来源与目标小问；PDF/图片中的公式、条件和图形对照原页。区分已知、构造、待证和推出；不把图上看似成立的关系当条件。明确对象、定义域、分情况和关键推理。缺失条件妨碍求解时标 `blocked`，说明缺失，不自造替代题。概念课可只推导目标范围内的关系，但须说明范围。
2. **按具体疑点核验。** 先指出需核对的公式、边界、计数或极值结论，再选能检出该类错误的方法：代回、独立推导、符号运算、有限枚举或数值交叉检查。程序用于确有必要的重复计算或实现核对；不默认叠加 SymPy、扫描和优化算法，不以断言数量代替依据。有限采样不能证明一般结论；脚本报错先区分推导、实现与断言问题，有依据后修复，不能为了通过删掉有效检查。数学关系尚未明确时，不开始查实现栈。
3. **判断需要什么表示。** 写明学生前置知识、最可能卡住的一步、关键句和一个检查理解的问题。图形是否帮助解释这个难点？需要操作才能观察关键变化吗？据此选 `none`、`static` 或 `interactive` 并给一句理由；确有取舍时比较两种表示，不为明显简单的任务凑方案。`none` 给出解答及不画理由，保留内容核验与审校，跳过工具选型、原型、HTML 和浏览器环节。不能因工具不足把必要的交互降为静态。
4. **选实现路径，写讲稿并试作。** 先确认数学模型和解释呈现分别需要什么，再按“配置可覆盖 → 已有工具可组合 → 真实能力缺口需扩展”判断；没有题型模块不等于必须新增公共模块。按路径读取资料。先写能连续读懂的讲稿，再按理解环节分步，分配图、文、操作各自的任务；关键环节的学习目标、必要信息、呈现方式与检查状态并入 `analysis.md`，简单任务可简记。只试作最难的关系和容易失效的边界，能表达后补齐课件；不为每步另建原型。预览明确标记，不能写入正式交付目录。
5. **冻结输入，独立教学审校。** 用实际源稿、渲染文字、对象身份、代表状态和必要信息约定执行审校协议。只修阻止项及必要关联内容，非阻止建议默认登记；周期、预算与停止条件只在协议维护。两条已接入构建路径按当前输入查门禁，缺记录、未完成、阻止或过期时拒绝正式导出。低层组合仍须独立审校并留存同源证据，不能因未接入脚本门禁跳过，也不能冒称自动门禁覆盖。
6. **正式生成并验收。** 审校通过后生成，按已读验收标准检查实际学生可见信息、关键状态和操作；数学、教学、视觉、交互分别留证。普通状态用程序遍历，关键图文用截图核对；相关截图批量查看、集中修复，复用本地服务。只复测改动影响的状态，不每改一处就全量重截。装饰性省略或合理滚动满足标准后即保留；必要信息缺失必须修。缺浏览器能力如实标未实测，受策略阻止时不绕过。
7. **交付并停止。** 适合画：HTML、关键句、已测范围/限制；不适合：正确的简短解答和不画理由。新任务只要求当前产物可用，不自动扩展成公共模块入库或多副本维护；确实修改了共享 Skill 时，在验证通过后集中同步本次改动。测试任务另留选题、判定和修订证据。未经要求不发布到外网。

## 不可遗漏的约束

- **揭示一致：** 图、公式、图例、说明、无障碍文本都服从当前步骤；不能第一步隐藏答案文字却在顶点标签或图下注释提前给答案。复习场景可以提前给结论，但要有明确教学目的。
- **同一状态：** 从同一模型派生图形、数值和解释。原题固定条件不做普通滑块。探索原题允许的动点与修改题目条件分开；变式开启时同步解释或清楚并排对照。恢复原题参数不应强迫退回第一步；重新讲解用另一按钮。
- **数学诚实：** 精确值与近似值分开，约数用 `≈`/“约”；有限采样、实例展示、符号恒等验证、一般证明各有范围。条件不足和“不值得画”不是同一结论。
- **表示诚实：** 平移展示对应点/位移，导数展示切线/增减关系，空间角在适当截面展示；屏幕上的长度角度不等于三维真实值。点拖动必须保持已知约束，不以结论约束构图。
- **课堂可用：** 图、当前关键公式、当前解释和推进按钮尽量同屏；主要公式与标签清晰，隐藏/越界/重合对象有明确处理。颜色同时配文字或线型。老师控制节奏，无自动循环动画。
- **中文表达：** 语义必须前后连贯，符合中国人的用语习惯和自然的课堂讲解方式。不得省略理解所必需的主语、指代对象、条件及推理关系；不为压缩字数写成提纲、口号或翻译腔。内容较多时分句或分步呈现，不能删去承接关系。
- **审校前置：** 正式 HTML 只能来自当前版本的已审校讲稿；不合格、未完成或过期审校必须阻止导出。不把非阻止项当作继续循环的理由；不为达标删除失败断言；不以新增脚本、文档或测试通过宣称教学问题已解决。
- **讲解可理解：** 面向老师使用，不等于页面可以只写教师解题提纲。按学生前置知识写完整关系，先明确对象再解释操作与理由；关键转化不能依靠教师自行补全。用户反馈“读不懂”时，按[教学设计](references/pedagogy.md)检查指代、术语和推理缺口，不能只替换词语。数学及交互通过不等于教学通过。

## 配套资源与边界

- **小核心，按需扩展：** 已有模块由配置生成；新题一般只写模型参数、讲解和验证。能力清单区分已实现模块、低层工具、尚未接入的库。不能因为文档提到 Three.js 就宣称可直接调用。
- **配置与组合：** 配置路径（build_lesson + modules + player）用于已有模块和共享能力扩展；lesson.js 是兼容用的低层步骤壳，不再新增能力。已有工具可表达的特殊题目可直接组合，不必先新增公共模块。入口见[配置示例](references/examples.md)。
- **示例使用：** 内置配置用于了解模型、讲解步骤和控件声明，不附历史审校记录。复制后针对当前任务重新核验并审校；正式导出仍受门禁约束。
- **同题多版本管理：** 同一题目存在多个版本（不同教学目的或不同生成路径）时，先列来源清单（目标 HTML、讲稿源、构建方式、分发位置）；教学目标相同的版本优先共用讲稿数据，目标不同的版本明确写出区别，保持模型与呈现分离，不为共享文案搭建庞大框架。修改任一版本后重建，并在实际 HTML 中核对本路径已改；不把一条路径的修改当作另一条已修复。
- 主要使用者是老师，输出面向备课与课堂演示，不默认扩展学生端、家长端或账户平台。

- 工具是轻量 SVG、坐标与向量辅助，不是通用解题器；数学由调用 Skill 的 Agent 推导并核验。
- 内置配置涵盖二次函数与圆线关系。低层工具提供空间点的正交投影；复杂遮挡或曲面按工具表选择专用库。
- `scripts/check_package.py` 检查打包结构与引用；`scripts/bundle.py` 只嵌入明确标记的本地资源，不执行题目文字。
- 能力范围以模块清单为准；未实现的题型须判断组合或扩展，不宣称覆盖所有题目。
